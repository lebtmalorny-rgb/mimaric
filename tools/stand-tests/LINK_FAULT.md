# Сетевой отказ на 300 секунд: Python 3.11

`link_fault.py` — отдельный параметризованный адаптер внесения сетевого отказа.
Он отключает заданный Linux-интерфейс на compute, выдерживает заданный интервал
и пытается вернуть интерфейс в исходное административное состояние UP.

Этот отдельный CLI не читает inventory/globals и не проверяет OpenStack.
Полный [stand_test.py runner](README.md) использует тот же worker через Ansible
и проверяет два сценария, включая автоматический возврат хоста через Mistral.

## Требования

- Оператор: Python 3.11, OpenSSH; Linux или macOS. Сторонних Python-пакетов нет.
- Compute: Linux, Python 3.11+, iproute2 с `ip -j`, systemd с поддержкой
  `Type=exec`, `RuntimeMaxSec` и transient `ExecStopPost`.
- Рабочий SSH-ключ и заранее проверенный host key. Парольный вход, запрос sudo
  password и автоматическое принятие неизвестного host key не используются.
- На compute нужны root-права: по умолчанию используется `sudo -n`; при входе
  сразу под root передайте `--no-sudo`.
- Постоянные журналы размещаются на локальных файловых системах с поддержкой
  `flock`, атомарного rename и fsync. Размещение на NFS не поддерживается.

Перед изменяющим запуском оператор выбирает выделенный тестовый compute и
проверяет состав ВМ, роль интерфейса, bond/VLAN, фактическую матрицу hostmonitor
и независимость BMC-пути. В этой версии нет автоматической проверки этих условий.
`plan` проверяет только синтаксис параметров, без SSH и чтения стенда.

## Параметры и запуск

Команды выполняются из корня репозитория. При копировании на операторскую машину
сохраните рядом оба файла: `link_fault.py` и `remote_fault.py`.

Задайте значения для своего стенда:

```bash
export TEST_HOST='operator@compute.example'
export TEST_INTERFACE='ens3'
export TEST_RUN_ID='nic-fault-001'
```

Просмотр задания без соединения со стендом:

```bash
python3.11 tools/stand-tests/link_fault.py plan \
  --host "$TEST_HOST" --interface "$TEST_INTERFACE" \
  --run-id "$TEST_RUN_ID" --duration 300
```

Внесение отказа — следующая команда действительно меняет интерфейс на compute:

```bash
python3.11 tools/stand-tests/link_fault.py start \
  --host "$TEST_HOST" --interface "$TEST_INTERFACE" \
  --run-id "$TEST_RUN_ID" --duration 300 --execute
```

`300` — значение по умолчанию; `--duration` можно опустить. Разрешён интервал
1–3600 секунд. `start` без `--execute` работает как локальный `plan`.

Операция асинхронная. При отключении management-интерфейса ответ SSH может
не дойти; это даст `UNKNOWN`, но не отменит запущенный на compute процесс.
После восстановления доступа проверяйте **тот же** run ID:

```bash
python3.11 tools/stand-tests/link_fault.py status \
  --host "$TEST_HOST" --interface "$TEST_INTERFACE" \
  --run-id "$TEST_RUN_ID" --duration 300
```

Досрочно вернуть интерфейс через доступный SSH-путь:

```bash
python3.11 tools/stand-tests/link_fault.py restore \
  --host "$TEST_HOST" --interface "$TEST_INTERFACE" \
  --run-id "$TEST_RUN_ID" --duration 300
```

Дополнительно: `--ssh-port 2222`, `--remote-python /usr/bin/python3.11`,
`--state-dir /private/local/path`. При `status`/`restore` передавайте те же
host, interface, port, duration и state-dir, что использовались при запуске.
Для fault, созданного полным stand_test.py, также передайте `--intent-nonce`
из `operations.fault.nonce` его отчёта: nonce входит в точную привязку request.

## Повторяемость и журнал

Оператор сохраняет привязку run ID к host/port/interface/duration и последний
JSON-ответ в `artifacts/link-fault/<run-id>/`. На compute находятся исходное
состояние, worker и журнал `/var/lib/powerops-link-test/<run-id>/`.
Каталоги имеют права 0700, файлы — 0600. Учётные данные не копируются в журнал.

- Повторный `start` с тем же ID только наблюдает существующий запуск. Нового
  отключения и продления срока нет, в том числе после потери ответа systemd.
- Другие параметры для существующего ID отклоняются. Для новой итерации нужен
  новый ID; новый fault на том же хосте запрещён до восстановления предыдущего.
- Изначально DOWN-интерфейс отклоняется и автоматически не поднимается.
- Перед изменениями сверяются boot ID, ifindex, MAC и имя устройства. Изменение
  загрузки или идентичности требует ручного разбора, без изменения новой сети.
- Повторный restore завершённого запуска не переписывает более поздние изменения
  интерфейса. Они отображаются как `observation_error`.
- Удаление журналов или изменение SSH alias так, что он указывает на другой
  сервер, нарушает контекст повторяемости. Журналы активного запуска не удалять.

При сбое между записью намерения и обращением к systemd возможен SUBMITTING без
действующей службы. Такой запуск автоматически не отправляется повторно.
Оператор проверяет одноимённую службу и журнал, затем использует `restore`
с тем же ID, если требуется завершить невыполненный запуск. Поздно стартовавший
worker увидит завершённый журнал и не отключит интерфейс.

## Как выдерживается время и выполняется возврат

До DOWN создаётся transient service `powerops-link-<run-id>.service` с
`ExecStopPost`, выполняющим восстановление. Сам worker сохраняет намерение,
запрашивает DOWN, подтверждает административный флаг и начинает отсчёт 300 секунд.
Наблюдения выполняются примерно раз в секунду; ранний UP даёт INTERRUPTED.

По истечении интервала worker восстанавливает UP. Если он аварийно завершился,
systemd вызывает тот же механизм через ExecStopPost, с тремя попытками и паузами
по две секунды. Перед каждой попыткой повторно проверяется идентичность устройства.
Ошибки записи журнала после DOWN не блокируют попытку восстановления сети.

Ожидание journal lock ограничено 10 секундами, одного внешнего вызова — 10
секундами. RuntimeMaxSec равен duration + 60, TimeoutStopSec — 150 секунд для
резервного восстановления. Это запас на ошибки и восстановление, а не требуемая
длительность штатного отказа. При исчерпании восстановления нужен оператор.
Точность до секунды при перегрузке ОС, suspend, зависании netlink/диска/systemd
или конфликтующих внешних изменениях не гарантируется.

**Если Masakari выключит compute, процесс и ExecStopPost на нём работать не смогут.**
Тест не выполняет power-on, не снимает maintenance и не включает Nova scheduling.
В этом отдельном сетевом CLI возврат питания после fencing остаётся ручным.
Полный stand_test.py выполняет его через Mistral. Восстановление сети само по себе не
отменяет принятое уведомление или уже начатое recovery.

## Результат

`COMPLETED` означает: наблюдался административный DOWN заданного интерфейса в
течение заданного интервала, затем подтверждён административный UP. Это не
доказательство непрерывного физического отказа, восстановления carrier, адресов,
маршрутов или прикладной связности. Короткое внешнее переключение между опросами
может остаться незамеченным. Для полной приёмки нужны отдельные сетевые пробы
и коррелированные журналы/состояния Consul, Masakari, Ironic и Nova.

| Значение | Смысл |
|---|---|
| PLAN | Только локальная проверка входа; соединения не было |
| SUBMITTING / DOWN | Запуск не завершён; состояние читать повторно |
| RESTORED + COMPLETED | Штатный административный цикл завершён |
| RESTORED + INTERRUPTED | UP восстановлен, но сценарий был прерван |
| RESTORED + NOT_APPLIED | Отказ не был применён; тест не засчитывается |
| NEEDS_OPERATOR / UNKNOWN / ERROR | Недостаточно доказательств; нужен разбор текущего ID |

Exit code: `0` — PLAN либо COMPLETED без ошибки свежего наблюдения;
`2` — незавершённый/неуспешный сценарий или ошибка параметров;
`3` — неизвестный результат удалённого запроса. Exit code команды `start` не
является подтверждением восстановления; проверяйте последующий `status`.

## Локальная проверка

```bash
python3.11 -m unittest discover -s tools/stand-tests/tests -v
```

Проверяются реальные файловые журналы и CLI под Python 3.11,
с заменой Linux/systemd/SSH и часов тестовыми адаптерами. Сетевые команды на
стенде не выполнялись. Реальные systemd, потеря SSH и взаимодействие с сетевым
менеджером ещё требуют отдельной стендовой проверки.

Основания для системного механизма:
[systemd.service](https://raw.githubusercontent.com/systemd/systemd/main/man/systemd.service.xml),
[ip-link](https://man7.org/linux/man-pages/man8/ip-link.8.html).
