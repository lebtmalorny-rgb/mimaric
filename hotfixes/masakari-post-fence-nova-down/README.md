## Поведение

Существующий `ironic_fence` теперь завершается только после двух проверок:

1. Ironic подтвердил стабильный `power off` прежним механизмом fencing.
2. Свежий запрос Nova `GET /os-services?host=<точное имя>&binary=nova-compute`
   вернул ровно один сервис этого хоста в состоянии `disabled/down`.

При `disabled/up` продолжается опрос. Ошибка API, неоднозначный или отсутствующий
сервис, неверное имя/binary, неизвестные state/status, повторное включение сервиса,
истечение срока или потеря координации не допускают переход к подготовке ВМ
и эвакуации. Запросы выполняются через python-novaclient, не через SDK response
cache. Нет SSH-проверок, записи `forced_down`, повторного запроса выключения
из-за ожидания Nova или автоматического power-on при откате.

Проверка встроена в действующий `ironic_fence`, поэтому распространяется на
`auto` и `reserved_host` без изменения task lists Kolla-Ansible. Прежняя пауза
`wait_period_after_service_update` до fencing не удаляется: этот патч добавляет
проверку после выключения, а не меняет политику обнаружения/отмены аварии.

После ошибки проверки Nova лог отката сохраняет факт **ранее подтверждённого**
выключения, но не утверждает, что перепроверил текущее физическое питание.
Возврат после аварии остаётся ручным. Nova остаётся disabled, Masakari maintenance
не снимается этим патчем.

## Параметры

Значения по умолчанию в коде Masakari:

```ini
[powerops]
nova_down_timeout = 180
poll_interval = 5
```

`nova_down_timeout` — новый положительный таймаут; отсчёт начинается после
подтверждённого fencing. `poll_interval` — существующий параметр, который также
используется проверкой Ironic. Если он уже переопределён, применяется его
действующее значение. Для стандартных значений менять конфиги не требуется:
нужен образ с исправленным кодом Masakari. При необходимости переопределения
параметра используйте штатный механизм доставки `[powerops]` в `masakari.conf`.

Nova-клиент и его Keystone-сессия создаются для чтения в native worker.
HTTP timeout передаётся самой сессии: установленный python-novaclient игнорирует
свой аргумент timeout при получении уже созданной сессии. Рабочий поток не даёт
блокирующему DNS задержать основной eventlet-поток восстановления. Нельзя
отключать eventlet thread pool (`EVENTLET_THREADPOOL_SIZE=0`): исполнение проверки
без отдельного native worker отклоняется.

Уже начатое чтение при истечении срока может закончиться позже; его результат
не продолжает восстановление и не меняет питание. Чтение, ещё ожидающее своей
очереди, после deadline не начинает новый API-вызов.

Граница гарантии: ограничены ожидание Nova, её аутентификация/API-чтение и опрос.
Существующие callbacks координации и persistence остаются в контексте engine
со своими прежними timeout/blocking-свойствами. `nova_down_timeout` не является
новым жёстким лимитом всей задачи, etcd, persistence, fencing или эвакуации.
Подтверждение Nova down также не доказывает готовность принимающего хоста,
ёмкость, доступность хранилища или отсутствие stale domains после возврата.

## Наложение

Перенести файл патча в корень исходников Masakari на базе указанного архива.
Не накладывать повторно предыдущие исправления, уже входящие в `0809`.

```bash
git status --short
git apply --check 0001-fix-wait-for-Nova-down-after-confirmed-fencing.patch
git apply 0001-fix-wait-for-Nova-down-after-confirmed-fencing.patch
```

Выполнять последнюю команду только после успешного `--check` и проверки
отсутствия пересекающихся локальных правок. При несовпадении базы остановиться,
не использовать `--reject` и не удалять конфликтующие части тестов вручную.

Образы пользователь собирает и переносит самостоятельно. Сборка и деплой
этим комплектом не выполняются.

## Что фиксировать в чистом стендовом прогоне

До отказа сохранить питание и состояния сервисов обоих compute, размещение ВМ,
время начала и отсутствие незавершённых операций. После отказа сопоставить по
хосту/notification UUID события:

```text
Ironic confirmed power off ... waiting ... for Nova disabled/down
Nova confirmed disabled/down ... host recovery may proceed
Call evacuate command ...
```

Вторая строка должна предшествовать вызову эвакуации. Если down не подтверждён,
должна быть явная ошибка проверки без последующего вызова evacuate в этой
попытке и без автоматического включения исходного хоста. Позднейшие попытки
Masakari анализировать отдельно по UUID/времени; механизм повторной обработки
уведомлений этим патчем не меняется.
