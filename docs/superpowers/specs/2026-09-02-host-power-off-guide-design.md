# Руководство по плановому выключению PowerOps — дизайн

## Цель

Создать отдельное короткое русскоязычное руководство `HOST_POWER_OFF.md` для
оператора, которому нужно безопасно выключить compute-хост через Mistral
workflow `power_ops.planned_power_off`.

## Граница документа

Руководство описывает только плановое выключение. Оно не запускает аварийную
Masakari notification, не описывает возврат хоста и не заменяет полный
`OPERATIONS.md`.

## Структура

1. Предварительные требования и загрузка OpenStack credentials.
2. Получение `SEGMENT_UUID` и точного `HOST` командами Masakari/OpenStack CLI.
3. Read-only сверка Masakari, Nova и Ironic перед изменением состояния.
4. Команда для пустого хоста с `instance_policy=require_empty`.
5. Команда для хоста с ВМ с `instance_policy=live_migrate`.
6. Альтернативная команда `instance_policy=stop` с явным описанием результата.
7. Наблюдение за Mistral execution и проверка конечного состояния.
8. Короткая памятка о безопасном поведении при ошибке.

## Примеры и безопасность

- Во всех примерах используются `compute-01` и явно фиктивный UUID сегмента.
- По умолчанию задано `allow_hard_off=false`.
- Для большого числа ВМ поясняется, что workflow обрабатывает их
  последовательно; список UUID вручную не передаётся.
- Хост считается успешно выключенным только после `SUCCESS` workflow и сверки
  фактических состояний Mistral, Nova, Masakari и Ironic.
- При ошибке после отключения Nova ожидается fail-safe состояние: хост может
  остаться включённым, Nova — disabled, Masakari — maintenance. Слепой повтор
  запрещён.
- Команды не выбирают автоматически первый сегмент или первый хост, чтобы не
  допустить выключения неверной машины.

## Проверка результата

После создания файла выполнить:

- проверку всех команд и имён workflow по `OPERATIONS.md` и PowerOps workbook;
- поиск любых незаполненных или временных маркеров;
- `git diff --check`;
- просмотр итогового Markdown как обычного текста на предмет читаемости и
  отсутствия неоднозначных инструкций.
