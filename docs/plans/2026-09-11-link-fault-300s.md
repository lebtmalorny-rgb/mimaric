# Parameterized link fault Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this focused adapter inline. Steps use checkbox syntax.

**Goal:** Deliver a Python 3.11 CLI accepting host/interface and a default 300-second network outage, with persistent run identity and systemd-managed restoration.

**Architecture:** The operator CLI sends a stdlib-only worker through SSH. Before any link change, the worker persists intent and starts a transient systemd service with ExecStopPost restoration and a runtime limit. Remote state is an atomic JSON journal under a private directory; this focused adapter does not implement the larger SQLite scenario catalog.

**Tech Stack:** Python 3.11 stdlib, OpenSSH, Linux iproute2 and systemd.

**Spec:** 2026-09-11-powerops-stand-runner-design.md, network fault adapter section. The user selected a 300-second fault with host/interface supplied as parameters.

## Global Constraints

- No live stand access or network mutations during development.
- Required host, interface and run ID; duration defaults to 300 seconds.
- Repeating a run ID must never inject a second outage or extend its duration.
- Root/systemd are needed only on the target. No credentials in command arguments.
- Network restoration is distinct from Masakari recovery; no automatic power-on or maintenance changes.
- Runtime verification below uses fake OS commands; it does not prove live fencing or network restoration.
